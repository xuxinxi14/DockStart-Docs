# 为什么结果不一致

## 简单概括

可复现不等于"在哪都跑得一模一样"。Docking 的搜索本身就带随机性，输入、参数、工具版本里只要有一处变了，结果就可能不同——而且很小的改动也可能带来明显的差异。

---

## 从运行记录开始排查

两次分数不同，先把两份运行记录放在一起看。DockStart 保存了当次输入、参数、命令和日志，可以逐项核对，而不必凭印象回忆。

建议先查输入文件与工具版本，再看 Box、评分函数和搜索参数。即使差异很小，也先把条件是否一致弄清楚，再判断它是否值得继续追查。

---

## 先建立正确的期待

```text
同样的输入 + 同样的参数 + 同样的工具版本
        ↓
可以复现（结果一致）

以上任何一项不同
        ↓
结果可能不同 —— 这不一定是错误
```

AutoDock Vina 官方 FAQ 里有一条很直接的说明：**输入的任何微小改动，产生的影响可能与换一个新的随机种子类似。**

也就是说，"改了一点点，结果却差很多"这件事本身是符合预期的，不是异常。

---

## 可能影响结果的因素

### 1. 输入结构

- 受体用的是哪个结构、哪条链、哪个模型；
- 有没有去掉水、金属、辅因子；
- AltLoc 选了哪一个；
- 缺失残基补没补。

**输入结构换了，等于换了一个问题。**

### 2. 结构准备

- 质子化状态；
- 形式电荷与拓扑；
- 氢原子怎么处理；
- 手性对不对。

这部分差异最隐蔽：两个文件看起来"差不多"，但里面的氢键网络已经变了。

### 3. Box（搜索空间）

- 中心在哪；
- 三个方向多大；
- 有没有盖住目标区域。

搜索范围之外的构象，程序不会去找。

### 4. 评分函数

```text
vina / vinardo / ad4
```

三者是**不同的评分模型**，数值不在同一把尺子上。

> Vina 和 Vinardo 的分数不能直接相减；ad4 和它们的分数同样不能直接比。

如果两次"同一个实验"其实换了评分函数，那结果不同是必然的，连"比较"这个动作本身都不成立。

### 5. 搜索彻底程度

- `exhaustiveness` 越高，搜得越透，也越慢；
- `exhaustiveness` 低的时候，同一个体系两次运行拿到不同结果很常见。

### 6. 随机种子（seed）

- 默认值是 0，意思是**由程序自动生成一个随机种子**；
- Vina 启动时会把实际用到的种子打印出来，比如：

```text
Performing docking (random seed: -1622165383) ...
```

所以在 DockStart 的 run 日志里，即使你从没手动设过种子，也能事后查出来那一次实际用的是哪个。

固定种子能提高可重复性，但**前提是其他输入和参数也要完全一致**。

### 7. CPU 与并行方式

- `cpu` 决定并行线程数；
- 并行方式一变，计算的执行顺序也可能跟着变。

### 8. DockStart 版本

不同版本可能在参数契约、默认值、校验规则上有差异。版本号建议一起记下来。

### 9. 第三方工具版本

```text
AutoDock Vina / RDKit / Meeko / AutoGrid4
```

Vina 版本变了可能影响搜索和评分；RDKit / Meeko 版本变了可能影响生成出来的 PDBQT 本身 —— 那就等于输入也变了。

### 10. 运行环境

- 操作系统与运行方式；
- 外部工具的实际二进制（同一个版本号的不同构建也可能不一样）。

---

## 排查顺序：从最确定的地方开始

**不要一上来就换参数。** 建议按这个顺序：

```text
1  确认两次用的是不是同一份输入文件（比 SHA256，别比文件名）
2  确认评分函数和 Box 六项是否一致
3  固定 seed，再跑一次
       ├─ 固定后一致了   → 之前的不一致来自搜索随机性
       └─ 固定后仍不一致 → 输入或参数是真的变了
4  确认 DockStart / Vina / Meeko / RDKit 版本一致
5  以上都排除了，再怀疑评分函数本身的近似
```

在 DockStart 里，第 1 步和第 2 步都有现成的东西可查：每个 run 目录里的 `metadata.json` 记着输入哈希和冻结参数，`config_snapshot.txt` 是当次实际用的配置。**把两个 run 的这两份文件放在一起看，差异点通常一下就出来了。**

第 3 步是分水岭：

```text
固定种子后还是不一致
    ↓
说明输入或参数真的变了（去查，而不是去换种子）

固定种子后就一致了
    ↓
说明之前只差在搜索随机性上
```

---

## 换种子有用吗？

分两种情况：

| 情况 | 换种子 |
|---|---|
| 搜索本来能找到正确构象，只是这次运气不好 | 可能有用 |
| 评分函数的最低点本身就不对应正确构象 | **没用**，换多少次都解决不了 |

所以换种子之前，更值得先检查的是**输入结构**和**搜索空间**。用换种子去解决"模型本身找不对"的问题，是徒劳的。

---

## 一个常见误区

| 你可能想说 | 问题在哪 |
|---|---|
| "两次结果一样，说明结果可靠" | 只说明可复现，不说明结论正确 |
| "两次结果不一样，说明软件有 bug" | 先排查输入、参数、版本和随机性 |
| "seed 固定了就该一模一样" | 还得其他输入、参数、工具版本也完全相同 |
| "换台电脑跑一遍就能验证" | 环境差异本身就会带来不同结果 |

---

## 总结

结果不同不一定是出错：搜索本身带随机性，而输入、参数、工具版本里任何一处变化都可能带来明显差异；排查时从最确定的地方（输入与版本）往里查。

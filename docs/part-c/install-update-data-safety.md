# 安装、更新和数据安全

## 简单概括

DockStart 是本地优先的桌面软件：对接、结构准备、项目记录、诊断全都在你自己机器上完成；它当前没有自动更新，升级要自己下载安装。你的科研数据不会上传，但项目文件和诊断报告里可能带着本机路径，分享前要自己检查一遍。

---

## 安装、升级与分享前的检查

安装前确认 profile 和文件哈希；升级前备份项目；分享前检查文件中是否带有本机路径或其他不打算公开的信息。

如果只想了解联网行为，可以直接看 [你的数据会不会联网](#你的数据会不会联网)。

---

## 安装

### v1.0.4 下载与校验

当前公开提供 `DockStart_1.0.4_Assisted_x64-setup.exe`，仅用于 Windows 10/11 x64。Basic / MSI 是本地候选，不在本次公开下载中。完整安装/升级/卸载与 GUI 发布验收仍待完成；请按试用版本使用。

[下载、SHA256 和逐步操作](./quick-start-v1-0-4.md)。已有 PDBQT 也可以直接使用 Assisted，普通 Vina 对接无需另外安装系统 Python、RDKit 或 AutoGrid4。

### 两个 profile 只能选一个

| | Basic profile | Assisted profile |
|---|---|---|
| 自带 AutoDock Vina | 有 | 有 |
| 自带结构准备工具链 | 没有 | 有（RDKit / Meeko） |
| 适合 | 已有 PDBQT | 需要从 PDB / SDF 准备 |

两个 profile 用的是**同一个应用身份**，所以**不能并行安装**。想换 profile，得先卸载再装。

怎么选：

```text
已经有 receptor.pdbqt 和 ligand.pdbqt   → Basic
只有 .pdb / .cif / .sdf / .mol / .mol2  → Assisted
只想先看看软件长什么样                  → 随便哪个，用内置示例
```

### 安装前请核对哈希

- 当前安装包**还没有做代码签名**，所以 Windows SmartScreen 可能提示"未知发布者"，这是预期现象；
- 安装前应当核对官方页面给出的 **SHA256**；
- 只有明确发布到官方 Releases 页面的产物，才算公开 Release。

**不要从第三方渠道下载安装包。**

## 更新

### 当前不提供自动更新

需要明确说一次：

> **DockStart 当前版本没有自动更新机制。** 它不会检查新版本，不会后台下载，也不会自动安装。

界面上显示的版本号是**编译期固定**的，不会联网比对。

所以升级完全是手动流程：

```text
查看官方渠道有没有发新版本
   ↓
下载新的安装包
   ↓
核对 SHA256
   ↓
安装（同一个应用身份，会替换现有安装）
```

### 升级时要注意什么

| 事项 | 说明 |
|---|---|
| 先备份项目目录 | 项目是相对路径结构，整体复制一份就行 |
| 不要手工改 `project.json` | 版本迁移交给软件处理，手改容易破坏 schema |
| 不把新项目直接交给旧版覆盖打开 | 是否可读取决于项目 schema 的兼容性，不能仅凭应用版本号保证拒绝或兼容；先备份 |
| 记下当前版本号 | 便于事后对照结果差异 |
| 工具链可能要重新检测 | 换了安装目录后，原先配的 Vina / Python 路径可能失效 |

## 工作目录与文件位置

### 项目建在哪里

**由你自己选。** 创建项目时指定一个目录，DockStart 会在下面按固定结构生成子目录：

```text
<你选择的目录>/<项目名>/
├─ project.json
├─ raw/  prepared/  preparation/
├─ configs/  runs/  results/  reports/  maps/
```

项目内部用**相对路径**记录，所以整个目录可以移动、复制、归档。

### 应用设置在哪里

设置文件是 `dockstart_settings.json`，里面存的是：

- 工具路径（Vina、Python、AutoGrid4）；
- 默认项目目录；
- 新项目的默认对接参数。

它可能出现的位置：

| 情况 | 位置 |
|---|---|
| 安装版运行 | 应用配置目录下（标识符 `org.dockstart.desktop`） |
| 源码运行或未设定 | 仓库根目录下 |
| 设置了环境变量 | 由该环境变量指定的路径覆盖 |

> 设置文件损坏时，DockStart 会**保留原文件并拒绝覆盖**，而不是静默重置。这是为了避免把你的配置悄悄清掉。

### 诊断报告在哪里

导出的诊断报告默认写到本机应用数据目录下的 `DockStart/diagnostics`，文件名带 UTC 时间戳。反馈问题时这个文件很有用。

## 临时文件

运行期会产生临时文件，但它们都遵守两条规则：

```text
尽量放在目标文件同目录（保证原子替换）
用完立即清理
```

主要有这几类：

- 原子写入的临时文件（写完马上替换并清理）；
- 输出目录可写性探针（立即删除）；
- 设置文件的写入探针（立即删除）；
- 水合后处理的审计重放目录（用系统临时目录，自动清理）；
- 导入大配体文件时的暂存目录（用完回收）。

**不要手工去删项目目录里的临时文件** —— 正常情况下你根本看不到它们；真看到了，说明某个进程可能异常退出，那该查的是进程，不是文件。

## 数据安全

### 软件层面的保护

| 机制 | 作用 |
|---|---|
| 原子写入 | 写失败时保留原文件，不会留下被截断的半成品 |
| 输入快照 | 每次运行冻结自己的输入副本，项目文件后来被改也不影响这次记录 |
| 哈希校验 | 运行产物被改动会被检测出来，而不会被当作正常数据 |
| revision 冲突检测 | 拒绝用旧数据覆盖新数据 |
| schema 迁移备份 | 迁移前先备份旧 `project.json` |
| 损坏文件 fail-closed | 读不出来的配置不会被静默覆盖 |

这些机制合起来只有一个目标：**宁可拒绝操作，也不悄悄破坏你的数据。**

### 你的数据会不会联网

日常的对接、结构准备、项目记录、诊断都**在本机进行**。

只有你**主动**使用在线结构搜索时才会联网（按 PDB ID / 关键词从 RCSB 检索，按 CID / 名称从 PubChem 检索）。诊断报告**不会上传**。

## 分享之前要注意什么

分享前，也要检查文件中附带的信息。

| 文件 | 可能包含 |
|---|---|
| `project.json` 与各类 JSON 记录 | 本机绝对路径 |
| 诊断报告 | 本机工具路径（报告本身也会提示"分享前可自行脱敏"） |
| 导出的归档 ZIP | 已有 JSON 里的本机路径（导出**不做匿名化**） |
| run 目录 | 你的输入结构与结果内容 |

建议：

```text
分享前
 ├─ 确认项目里没有不想公开的研究数据
 ├─ 检查是否含本机用户名 / 绝对路径
 ├─ 必要时复制一份再脱敏，不要在原件上改
 └─ 记住：归档 ZIP 是只读实验包，不是可直接恢复的项目备份
```

如果要在 GitHub Issues 里反馈问题，官方建议提供：DockStart 版本与安装 profile、Windows 版本、出问题的流程步骤、页面上的中文错误码与建议、脱敏后的诊断报告或最小复现项目。

**请不要公开未脱敏的本机路径、私有结构文件或研究数据。**

---

## 怎么避免误操作

```text
不要在 runs/ 里手工改文件
   → 哈希校验会判定为异常，结果会被拒绝读取

不要手工编辑 project.json
   → 用界面的功能改设置；schema 与 revision 交给软件维护

不要手工删除 preparation/ 或 maps/ 里的记录
   → 项目里的指针会指向不存在的记录

要改实验设计
   → 新建一次 run，而不是修改旧的运行记录

要换受体
   → 重新准备、重新审查；maps 与相关确认会随之失效，这是设计如此
```

---

## 总结

DockStart 的数据留在本机，但项目文件与诊断报告可能带着本机路径；升级要自己下载安装，分享任何文件前先自己检查一遍。
